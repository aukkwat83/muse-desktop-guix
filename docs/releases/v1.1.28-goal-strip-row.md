# v1.1.28 — Goal strip owns its row

The 1.1.26 composer goal strip was a flex item *inside*
`form#composer` (a row): it shared the prompt line with the textarea
and overflowed the edge instead of sitting on its own line.

## What changed

- `src/renderer/index.html` — `#goal-bar` moves out of the form to a
  sibling above it (same pattern as `#attach-bar` / `#prompt-queue`);
  the misleading `class="goal-bar"` is dropped (JS selects by id).
- `src/renderer/style.css`
  - Strip rules are id-scoped (`#goal-bar …`), own row, card aligned
    to the 20 px composer gutters, `overflow: hidden` backstop.
  - Responsive squeeze order: the objective ellipsizes first
    (`flex: 1 1 auto`, `min-width: 0`), then the meta
    (`flex: 0 1 auto` + ellipsis, was `flex: none`), the pause/resume
    button never shrinks.
  - Panel progress rules scoped under `.goal-block` (`.goal-bar`
    5 px track, `.goal-objective`) — the two meanings no longer merge
    (the strip used to inherit `height: 5px` + `overflow: hidden`
    from the track rule).
- `scripts/unit-test-css-guards.mjs` — two regression tests: the
  strip sits outside the composer form; no unscoped `.goal-bar` /
  `.goal-objective` block rules remain.

## Verification

- `css-guards`: 16/16 (incl. the 2 new tests)
- `npm test`: full suite green, e2e 77/77
- Live on Guix: real goal strip on its own row above the composer at
  full width and at a narrowed window, no overflow; pause/resume
  button intact
