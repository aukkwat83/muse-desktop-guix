# v1.1.27 — Thread-overview hotfix (`subKindOf`)

Follow-up to v1.1.26, caught by live screenshot verification on Guix
instead of the suite: the overview/history agent code called
`agentToolMeta(subKindOf(t))`, but no `subKindOf` helper exists in
either `app.js` or `turn-view.js`. Every transcript with tool history
painted `Can't find variable: subKindOf` (and a blank transcript), and
the `▦` overview's Subagents section could never render rows.

## What changed

- `src/renderer/app.js`
  - History + overview agent classification goes through
    `agentToolMeta(tool)` directly (it reads `tool.rawInput` itself).
  - Overview agent rows: label from `agentSubtitle(tool)`, status
    words mirroring the tool rows — `ทำงานเบื้องหลัง` for background
    agents, else the shared `toolStatusLabel(tool.status)`. (The old
    code read `.status` off a string return and `label`/`icon` keys
    the helper never returns, so every row would have read `เสร็จ`.)
  - Settled text-only turns with a persisted `durationMs` keep their
    header: the live `กำลังทำ…` settles into a visible `ทำไป Xs`
    instead of vanishing on reload. Pre-1.1.26 transcripts without a
    duration stay bare like the reference's plain answers.
- `scripts/unit-test-renderer-contracts.mjs` (new, wired into
  `unit-test-all.mjs`): renderer no-undef scan (regex/template aware),
  named-import resolution against source-module exports, and the
  `agentToolMeta` / `agentSubtitle` / `toolDisplayState` shapes the
  overview consumes. Fails on the 1.1.26 tree at exactly the three
  `subKindOf` sites; passes on this tree.

## Verification

- `renderer-contracts`: 4/4 (negative control vs `HEAD:app.js`: 3/4,
  naming the three `subKindOf` sites)
- `npm test`: full suite green (40 suites incl. the new one), e2e 77/77
- Live on Guix: goal chat transcript renders again, `▦` overview opens
  with Subagents/Tasks/Goal, composer goal strip + `agents n/m` chip
  confirmed on screenshots
