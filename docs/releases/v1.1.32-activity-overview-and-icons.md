# v1.1.32 — ป๊อปอัปภาพรวม activity + ชุดไอคอนเดียวกันทั้งแอป

> Previous: [documented v1.1.29](https://github.com/aukkwat83/muse-desktop-guix/blob/main/docs/releases/v1.1.29-overview-wire-fallback.md) ·
> วันที่: 2026-10-08 · base: `main@f2c86b8` · ไม่มีรีลีสคั่น 1.1.30/1.1.31

รีลีสนี้ส่งมอบสองส่วนหลัก: **ป๊อปอัปภาพรวม goal/task/subagent**
และ **ชุดไอคอน SVG + การจัดบาลานซ์ฟอนต์ทั้ง UI**
พร้อมการเพิ่มไอคอน SVG บน chrome โดยคงขอบเขต sanitizer เดิมไว้
การส่งออกแผนภาพที่เชื่อถือได้ และการรองรับจอแคบ 560px

ลิงก์ไฟล์ทั้งหมดในโน้ตนี้ชี้แท็ก `v1.1.32` ของ repo นี้
(`https://github.com/aukkwat83/muse-desktop-guix`)
จึงอ่านโน้ตฉบับนี้เป็น GitHub Release body ได้โดยตรง

## 1. ป๊อปอัปภาพรวมแบบ popup-only — อะไรอยู่ตรงไหน

- **ป๊อปอัปภาพรวม** (ปุ่มไอคอน grid บน topbar):
  ภาพรวมละเอียดของแชท/session ที่เลือก —
  **goal + tasks + subagents** อยู่ในที่เดียว
  ([overview-panel.js](https://github.com/aukkwat83/muse-desktop-guix/blob/v1.1.32/src/renderer/overview-panel.js),
  เปิดผ่าน `popover.js → openPanel`)
- **แผงขวา (right rail)**: มีเฉพาะ **session + ค่าใช้จ่าย**
  ซ่อนเป็นค่าเริ่มต้นเหมือนเดิม เปิดด้วยปุ่ม panel บน topbar
- **MCP** มีป๊อปอัปของตัวเอง (กดปุ่ม MCP pill) ไม่ได้อยู่ในแผงขวา
- **chip แบบ compact + แถบ goal บน composer** ยังคงอยู่เหมือนเดิม
  เป็นทางเข้าแบบย่อ

section Subagents ในป๊อปอัปแสดง **union เต็มรูปแบบ**:
แถว agent ของ live turn รวมกับ child ในทะเบียน wire ของเซิร์ฟเวอร์
ตัดซ้ำด้วย durable link (`tool.agentLink → registry itemId`)
**ไม่มีการตัดจำนวนสูงสุด** และ reminder แต่ละตัวแสดงเดี่ยว ๆ
พร้อม drill ลง session ของตัวเองได้โดยตรงจากป๊อปอัป —
แถวที่ไม่มี link จะแสดงแบบ drill ไม่ได้อย่างตรงไปตรงมา

## 2. จำนวน ชื่อ ซับเซสชันซ้อน อัปเดตสด การรักษา draft/focus

- **จำนวนสอดคล้องกัน**: `unionSubagentCounts()` เป็นแหล่งนับเดียว
  ของทั้ง agents chip และหัวป๊อปอัป (running/total จาก union เดียวกัน)
  ทั้งสองจึงสอดคล้องกันโดยโครงสร้างข้อมูลร่วม
- **ชื่อมีความหมาย**: เซิร์ฟเวอร์ส่ง `taskName/title/topic` เพิ่มใน
  `sanitizeChildItem()` และ normalize `task_name` → `taskName`
  ([msp-client.js](https://github.com/aukkwat83/muse-desktop-guix/blob/v1.1.32/src/server/msp-client.js))
  ฝั่ง UI ตั้งชื่อด้วย `subagentTitle()` แทนคำสั่งดิบ
- **ซับเซสชันซ้อน**: workflow record แสดงจำนวนลูก (`3 ›`) drill ลงไป
  ดู children ได้ทีละชั้น มีปุ่มย้อนกลับ; drill บางแบบมีปุ่ม popout
  เปิดเป็นหน้าต่าง child แยก (`child.js`) เฉพาะจุดที่มีปุ่มให้
- **อัปเดตสด**: เปิด drill ค้างไว้ ตัวเลข/สถานะ/ผลลัพธ์ patch ลงแถวเดิม
  (`drillShouldPoll()` หยุด poll เมื่องานลงจอดแล้ว ไม่เปลือง request)
- **รักษา draft/focus**: re-render ไม่ทำ scroll/fold/โฟกัส/ข้อความร่าง
  ในช่องส่ง (รวมตำแหน่ง caret) หาย มี regression test คุมไว้
- **คอนโทรลที่รองรับ**: goal มี pause/resume พร้อมตัวบอกสถานะ
  completed (ไม่มีคำสั่ง mark-done — ดูหัวข้อ 4),
  child มี หยุด/ทำต่อ/ส่งข้อความ เฉพาะชนิด/สถานะที่เส้นทาง MSP
  เดิมรองรับ (`subagentActions()` + endpoint
  `POST /api/chats/:id/subagents/:item/command`;
  เซิร์ฟเวอร์ตอบ 4xx อย่างมีความหมายเมื่อสั่งไม่ได้),
  drill มี refresh/back และ popout ตามจุดที่มีให้;
  ปุ่มซ่อน/ปิดคงพฤติกรรมคีย์บอร์ดเดิม

## 3. Native transcript — ของจริงเมื่อพิสูจน์ได้, fallback ตรงไปตรงมาเมื่อไม่ได้

`readSubagent()` เลือกโหมดโปร่งใส:

- พิสูจน์ parent-child log mapping ได้ →
  โหมด `native-log`: อ่าน transcript จริงของ child จาก retained log
  (`src/server/native-transcript.js`: หา parent dir จากตราประทับ
  `rec.parentSessionId` ของเรคคอร์ด — ไม่ใช่ `mspSessionId` ปัจจุบัน
  หลัง rotation, ตรวจ workspace, ตาม `child_session_bound`
  binding ไปยัง child log)
- พิสูจน์ไม่ได้ (เรคคอร์ดไม่มีตราประทับ, log เก่า/หาย, workspace
  ไม่ตรง, parent กำกวม) →
  fallback แบบ synthesized โหมดเดิม พร้อมบอกที่มาอย่างเปิดเผย
  ไม่ปนข้อมูลข้าม child กัน และไม่ throw เข้าเส้นทาง drill
- **สถานะรอบปัจจุบัน**: ดูจากรอบรันล่าสุดตรง ๆ —
  รอบที่ยังวิ่งอยู่แสดงว่ากำลังวิ่ง, รอบที่จบแล้วแสดงผลสุดท้ายของมัน
  (`nativeRunStatus()`)
- **ขีดจำกัด**: อ่านแบบ read-only, tail สูงสุด **1 MiB**
  (`NATIVE_LOG_MAX_BYTES`), แถว drill สูงสุด **200 รายการ**
  (`NATIVE_LOG_MAX_ITEMS`), บรรทัดเสียถูกนับและแสดงเป็น notice
- **ไม่เปิดเผยของต้องห้าม**: การกรองบังคับใช้ใน projection ของ
  `native-transcript.js` — ส่งเฉพาะข้อความ/เครื่องมือ/ผลลัพธ์
  ที่แสดงได้ ส่วน reasoning ภายใน, system context และ
  provider payload ไม่ถูกส่งออก

## 4. Goal ที่ persist — ผูกกับ session ต้นกำเนิด พร้อม guard ครบ

ผู้ใช้ได้: ปิดแล้วเปิดแชทมา goal ยังอยู่, สั่ง pause/resume ได้เมื่อมี
live agent, และไม่มีปุ่มหลอกให้กดตอนแชทเย็น

- ภาพ goal ถูก mirror ลงดิสก์ (`session-store.js → saveGoal()`
  เก็บคู่กับ `sessionId` ต้นกำเนิด)
- `normalizeGoalSnapshot()`: ปฏิเสธค่าที่ไม่ใช่ object (รวม array)
  ด้วย `null`; ส่วน object จะถูก normalize ใส่ค่าเริ่มต้นและ
  ตัดขอบเขตฟิลด์ (เช่น `objective`/`currentWork` ยาวสุด 4000 ตัวอักษร,
  `sessionId` ที่ไม่ใช่ string กลายเป็น `null`)
- เปิดแชทเย็น (cold) ที่มี goal ค้าง: แสดงสถานะพร้อม verb ที่ disabled —
  เซิร์ฟเวอร์ตอบ 409 เมื่อสั่งงานโดยไม่มี live agent
- **guard การ rotation**: agent session id ใหม่พิสูจน์ว่าเกิด rotation →
  goal เก่าถูก retire ทันที (eager hook + backstop,
  ส่ง event ครั้งเดียวต่อ rotation); resume ธรรมดาที่ id เดิมคง goal ไว้
- **guard response ค้าง/null-SSE**: repaint ไล่ตาม event จริง,
  response ค้างจาก session เก่าไม่ทับสถานะใหม่

## 5. ไอคอน SVG ชุดเดียว + ฟอนต์ + a11y + เลย์เอาต์จอแคบ

ผู้ใช้ได้: ปุ่มและเมนูทั้งแอปอ่านออกตรงกันทุกธีม ไม่มีกล่องสี่เหลี่ยม
tofu, ข้อความไทยครบถ้วน, ใช้งานที่ 560px ได้จริง

- **44 ไอคอน** (`src/renderer/icons.js`):
  viewBox 24px, stroke มน ~1.8, `currentColor`,
  แสดง 16px ใน UI ทั่วไป / 14px ในแถวแน่นและเมนู / 20px ที่ปุ่มเด่น
  (send, brand) ครอบคลุม HTML นิ่งและตัว render ทุกพื้นผิวหลัก —
  sidebar/group/session, เมนู, topbar, composer, find, popover,
  ป๊อปอัป, หน้าต่าง child, แผงขวา/MCP/tasks, ปุ่มบน markdown,
  คิว, หน้า debug — รวมถึงทุกสถานะ pending/success/error
  ผ่าน helper กลาง (`setIcon/setIconLabel/updateIconLabel`)
  เพื่อไม่ให้การอัปเดตข้อความลบ SVG
- **ฟอนต์**: สแตก `--font-ui` ใช้ฟอนต์ที่ติดตั้งในเครื่อง
  (หน้า Latin/แพลตฟอร์ม + Inter, fallback ไทย Sarabun/Thonburi)
  พร้อม fallback ของแพลตฟอร์ม — **ไม่มีการดาวน์โหลดฟอนต์เพิ่ม
  ตอนรัน** และไม่มีการคัดลอก asset สงวนสิทธิ์ของ Codex
- **สเกล**: control 13–14px, body 14px, หัวข้อ 16px,
  metadata ที่อ่านได้ 12px (console ของ tool คงอัตราส่วน 3:4
  ที่ 10.5px และไม่ใช้ 10.5px กับ metadata อื่น), พื้นล่างสุด 11px
- **วรรณยุกต์ไทยไม่ถูกตัด** ในส่วน UI ที่เปลี่ยนในรีลีสนี้:
  one-liner ที่มี ellipsis มี padding-top กัน
  (sidebar, title, เมนู, แถบ goal, แผง)
- **ชื่อเต็มใน sidebar 230px**: ปุ่ม action ลอยทับท้ายแถวแบบ
  overlay เมื่อ hover/focus (คลิกทะลุตอนซ่อน) ไม่กินความกว้างชื่อ
  ร่วมกับปุ่มหัว sidebar ขนาด 32px ตายตัว
- **a11y** ในส่วนที่เปลี่ยน/ทดสอบ: ปุ่มไอคอนล้วนมีชื่อเข้าถึงได้;
  ตัวเลือกแบบ checked ในเมนูเป็น `menuitemradio` +
  `aria-checked` true/false (action ธรรมดายังเป็น `menuitem`);
  ปุ่มที่มีข้อความใช้ชื่อจากข้อความที่เห็นจริง
- **จอแคบ**: เฮดเดอร์ห่อบรรทัดที่ ≤900px —
  ก่อน: ที่ 560px ปุ่ม find/stop/overview/panel หลุดจอ
  (`scrollWidth` 1089px); หลัง: บรรทัดแรกมี title +
  ปุ่มหลักครบ 4 ปุ่ม บรรทัดสองเป็น chips ที่ห่อ/ย่อได้
  ไม่มี overflow แนวนอน

## 6. Chrome บน markdown ที่ sanitize แล้ว + ส่งออกแผนภาพอย่างปลอดภัย

ผู้ใช้ได้: ปุ่ม copy/download บน code และแผนภาพแสดงไอคอนชัด
ทุกสถานะ กดซ้ำได้หลัง feedback; การส่งออกแผนภาพไว้ใจได้ —
มีของจริงถึง export ไม่มีก็บอกล้มเหลวตรง ๆ

- sanitizer strip `<svg>` ทุกชิ้นจาก output ของโมเดล
  (เส้นแบ่งความเชื่อใจเดิม) แล้ว `decorateChromeIcons()`
  สร้างไอคอน registry ของแอปเองทับปุ่ม copy/download **หลัง**
  sanitize (idempotent ข้ามทุกเส้นทางการแทรก chrome)
  ไอคอนจึงมี `viewBox="0 0 24 24"` ครบ และรอดทุก flash
- ตัว builder (`codeBlockHtml`, `diagramActionButtonsHtml`)
  ปล่อยปุ่มแบบ text-only; mapping ไอคอนเป็นฟังก์ชัน pure
  (`chromeRestingIcon`) มีเทสต์คุม
- **ส่งออกแผนภาพ**: `diagramSvgInCard()` เลือกเฉพาะ SVG เนื้อหา
  ที่ paint แล้ว (`.md-mermaid`/`.md-echarts`, ไม่เอา `.ico`) —
  ไม่มีไดอะแกรม = รายงานล้มเหลวตรง ๆ ไม่ export ไอคอน

## 7. วิธีใช้ (ผู้ใช้)

1. เปิดป๊อปอัปภาพรวม: ปุ่ม grid บน topbar —
   เห็น goal + progress, tasks (พับ/กางกลุ่มได้), subagents แบบ union
2. คลิกแถว subagent เพื่อ drill: ดู preview → ข้อความ/ผลลัพธ์ →
   จุดที่มีปุ่ม popout เปิดหน้าต่าง child แยกได้, refresh อ่านใหม่,
   back กลับชั้นนอก
3. สั่ง goal: ปุ่ม หยุดชั่วคราว/ทำต่อ บนแถบ goal หรือในป๊อปอัป
   (รีลีสนี้มี pause/resume + ตัวบอก completed; แชทเย็นปุ่ม
   disabled พร้อมคำอธิบาย ไม่กดลม)
4. สั่ง child: ปุ่ม หยุด/ทำต่อ/ส่งข้อความ บนแถวที่รองรับ
   (เฉพาะชนิด/สถานะที่เส้นทาง MSP เดิมรองรับ)
5. ส่งออกแผนภาพ: ปุ่ม Mermaid/SVG/PNG บน chrome ของการ์ด —
   ระหว่างทำ/สำเร็จ/ล้มเหลวมีไอคอน+ข้อความบอกชัด กดซ้ำได้หลัง restore
6. จอแคบ: ลดเหลือ 560px เฮดเดอร์ห่อสองบรรทัดเอง ปุ่มหลักยังกดได้ครบ
