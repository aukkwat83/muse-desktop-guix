# v1.1.38 — Contributor locked on, wonder models priced

Previous: v1.1.37

An end-to-end audit of this deployment (wonder-full model, contributor
billing, `max` effort) found the wire path healthy — the agent log for a
fresh desktop chat shows `model_id=muse-wonder-full-1.0`, a
`reasoning_effort_reconfigure` with `effective=max` from `muse_desktop`,
and the provider facet billing `muse-wonder-full-1.0-contributor` — but
two display/guard gaps remained: the cost badge priced every wonder
session at the standard `default` row (~18x over the contributor bill),
and one stray click on the header pill (v1.1.37) silently switched the
whole deployment to standard billing. This release closes both.

## What changed

- `src/server/contributor.js` + `src/server/index.js` +
  `src/server/sessions.js` — contributor lock, ON by default. Boot
  forces `contributor_mode_enabled=true` back (was: explicit opt-out
  honored forever), `POST /api/contributor {enabled:false}` is refused
  with 403, and `prompt()` reverts an external flip to standard before
  the turn can run. Only an explicit `MUSE_DESKTOP_CONTRIBUTOR_LOCK=0`
  re-enables the opt-out; a malformed settings file is still never
  rewritten. Every contributor state now carries `locked`, and the boot
  log prints it.
- `src/renderer/app.js` — under lock the contrib-chip renders disabled
  with a "locked by deployment" title; `toggleContributor()` returns
  early, so no renderer path can reach the off-switch.
- `src/server/pricing.js` + `src/renderer/rightbar.js` — wonder rows
  priced: `muse-wonder-full-1.0`, `muse-wonder-1.0` and their
  `-contributor` siblings ride the spark public rates until a
  wonder-specific rate is published (built-in table stays `estimated`).
  New `default-contributor` fallback: an unlisted model on contributor
  billing falls to the contributor default, never the standard row —
  in both the server table and the renderer mirror. An env-override
  table without the row inherits the built-in one.
- `scripts/deploy.sh` + `scripts/linux-launch.sh` — pin
  `MUSE_DESKTOP_CONTRIBUTOR_LOCK` (default 1) in the host env and
  document it in `--help`.
- Tests: contributor 12 → 17 cases (lock default, boot force, switch
  refusal, external-flip revert, lock beats `CONTRIBUTOR_DEFAULT=0`);
  pricing pins wonder matching + the contributor fallback (replacing
  the case that locked in the old standard fallthrough); new E2E step
  boots a locked host (switch 403s, prompt reverts an external flip).
  The E2E harness main host now runs unlocked so the switch round-trip
  stays covered.
- Shared `?v=` + package version → 1.1.38 together (BUG-078);
  `rightbar.js?v=1.2.2` for the changed module.
