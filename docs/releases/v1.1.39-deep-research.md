# v1.1.39 — Deep Research: ปุ่มข้าง contributor + `/deep-research`

Previous: v1.1.38 · วันที่: 2026-10-13

## สรุปหนึ่งบรรทัด

Muse Desktop มีโหมดวิจัยเชิงลึกแล้ว: ปุ่ม **deep research** ในแถบหัว
(ข้างปุ่ม contributor) เปิดค้างแยกตามแชท หรือพิมพ์
`/deep-research <หัวข้อ>` ในช่องแชทก็ได้ผลเดียวกันแบบครั้งเดียว —
agent จะค้นหลายแหล่ง ตรวจโต้แย้ง และตอบเป็นรายงานพร้อมลิงก์อ้างอิง
ในเทิร์นนั้นเลย

## ที่มา / ปัญหาก่อนแก้

- `/deep-research` เป็น bundled workflow skill ที่ฝังใน binary ของ
  **Muse** (fan-out ค้นเว็บ → fetch แหล่งข้อมูล → adversarial
  verify → สังเคราะห์รายงานมีอ้างอิง) ไม่ใช่ไฟล์ skill ที่ copy มาได้
- **Muse ไม่มี skill นี้** (`muse skills list` ไม่มี) และ desktop
  ก็ไม่รู้จัก slash นี้นอกจาก `/plan`, `/ask`, `/always-approve`
  (BUG-053) — พิมพ์ไปจะได้ข้อความเตือน "ไม่รู้จักคำสั่ง" แล้วข้อความ
  ถูกส่งเป็น prompt ดิบ ผลลัพธ์ขึ้นกับโมเดล improvise เอง ไม่ใช่
  กระบวนการวิจัยที่มีขั้นตอนบังคับ

## วิธีใช้

| การกระทำ | ผล |
|---|---|
| กดปุ่ม `deep research` | เปิด/ปิดโหมดวิจัยเชิงลึก เฉพาะแชทที่เปิดอยู่ เปิดค้างจนกดปิด |
| `/deep-research <หัวข้อ>` | วิจัยหัวข้อนั้นทันทีครั้งเดียว ไม่เปลี่ยนสถานะปุ่ม |
| `/deep-research` | สลับปุ่มของแชทนี้ |
| `/deep-research on` / `off` | เปิด/ปิดปุ่มของแชทนี้ตรง ๆ |

- สถานะปุ่มจำแยกตามแชทใน sessionStorage (`kd.deepResearch.<chatId>`
  แบบเดียวกับ draft) รีโหลดหน้าแล้วยังอยู่ ไม่รั่วไปแชทข้าง ๆ
- ปุ่มที่เปิดอยู่ใช้สีคู่เดียวกับ pill busy ที่ผ่าน contrast audit แล้ว
  และมี `aria-pressed` บอกสถานะ

## กลไก

1. **Renderer** (`src/renderer/deep-research.js`, `slash-commands.js`,
   `app.js`): ปุ่มและ slash แปลงเป็น flag `deepResearch: true` ที่แนบไป
   กับ `POST /api/chats/:id/prompt` คิวรอส่ง (รวม requeue หลัง 409)
   เก็บ flag ไว้ต่อรายการ ไม่หายตอน dispatch
2. **Server** (`src/server/deep-research.js`, `sessions.js`): เมื่อ
   flag มา server ห่อหัวข้อด้วยคำสั่งวิจัยเชิงลึก **บนสายส่งเท่านั้น**
   (สัญญาเดียวกับ session-recovery preamble) — ข้อความที่เก็บใน
   transcript ยังเป็นหัวข้อเดิมของผู้ใช้คำต่อคำ พร้อม
   `meta.deepResearch: true` ไว้บอกว่าเทิร์นไหนเป็นงานวิจัย
3. คำสั่งวิจัยที่ห่อไป: (1) ถ้าคำถามกว้างเกิน (ขาดงบ/พื้นที่/
   use case/ช่วงเวลา) ให้ถามแคบขอบเขต 2-3 ข้อก่อนแล้วหยุด
   (2) แตกเป็นคำถามย่อยแล้วค้นเองด้วย web_search/web_fetch หลายแหล่ง
   อิสระ เน้นแหล่งปฐมภูมิและเปิดอ่านหน้าเต็ม (3) ตรวจโต้แย้งทุกข้อ
   สรุปสำคัญ เทียบอย่างน้อย 2 แหล่งอิสระ แหล่งขัดกันต้องระบุ
   (4) ตอบเป็นรายงานในภาษาของคำถาม นำด้วยข้อสรุป ใส่ citation
   ทุกข้อสรุปสำคัญ มีหัวข้อ disagreements/gaps วันที่ของแหล่งข้อมูล
   และ mark สิ่งที่ยืนยันไม่ได้ว่า unverified
4. Retry หลัง rotate session (history-incompatible / MCP-audit)
   ส่ง flag ต่อให้ด้วย งานวิจัยไม่หลุดกลางทาง

## บทเรียนจาก Live E2E (สำคัญ)

รอบแรกของ harness สั่งให้ agent "ใช้ Workflow tool แตก subagent
ขนานกัน" — E2E กับ CLI จริงจับได้ว่าใช้ไม่ได้บน desktop:

- โมเดล launch workflow แล้ว **จบเทิร์นเปล่าใน 68 วินาที**
- workflow ทำงานครบ 5 children ใน ~15 นาที (web_search/web_fetch
  จริง ดูได้จาก `muse export` ฝั่ง CLI) แต่ **synthesis ไม่เคยลง
  transcript** เพราะ background workflow ไม่ปลุกเทิร์นต่อใน
  desktop session ผู้ใช้เห็นเทิร์นว่างถาวร

จึงแก้ harness เป็น **วิจัย inline ในเทิร์นเดียว ห้าม Workflow/
subagent และบังคับจบเทิร์นด้วยรายงานเต็ม** มี regression guard
ล็อกข้อความนี้ไว้ใน unit test แล้ว รัน E2E ซ้ำกับหัวข้อเดิม
(เทียบสเปก Raspberry Pi 5 กับ Orange Pi 5 จากเว็บผู้ผลิต):

- เทิร์นเดียวจบใน 321 วินาที ได้รายงานไทย 6,034 อักขระ
- ลิงก์อ้างอิง 23 ลิงก์ จาก 7 โดเมน (raspberrypi.com,
  orangepi.org, github.com, cnx-software.com ฯลฯ)
- ข้อเท็จจริงหลักถูก: BCM2712 (Pi 5) / RK3588S (Orange Pi 5)
  พร้อมหัวข้อแหล่งขัดกันและจุด unverified
- ยืนยัน stack เดียวกับ CLI: เอา `mspSessionId` ของแชทไป
  `muse export --session <id>` เปิด transcript ฝั่ง CLI เจอ
  marker `[DEEP RESEARCH — Muse Desktop]`, web_search 41 ครั้ง,
  web_fetch 139 ครั้ง, โมเดล muse-spark-1.3 เรท contributor

## ขอบเขตที่ต้องรู้

- นี่คือ harness เทียบเท่าที่ desktop สั่ง Muse ให้ทำตามขั้นตอน
  ไม่ใช่ workflow script ต้นฉบับของ Muse (ฝังใน binary
  ของเขา ไม่มีไฟล์ให้ port) — คุณภาพขึ้นกับโมเดลทำตามคำสั่ง
  ไม่ใช่การบังคับระดับโค้ด
- งานวิจัยกินเวลาและ token มากกว่างานปกติหลายเท่า (เคสทดสอบ
  ~5 นาที) ปุ่มเปิดค้างจะทำให้ทุกข้อความในแชทนั้นเป็นงานวิจัย
- ใช้ได้เฉพาะผ่าน Muse Desktop (ปุ่ม/slash ของ client นี้)
  พิมพ์ `/deep-research` ใน Muse TUI โดยตรงยังไม่มีผลพิเศษ
