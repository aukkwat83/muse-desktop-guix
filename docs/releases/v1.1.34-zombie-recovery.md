# v1.1.34 — Zombie-window recovery + rail heading removal

Previous: v1.1.33

Bug: the shell's X surface died outside GTK (`GdkSurface unexpectedly
destroyed` — no widget signal fires, the GtkWindow stays listed and keeps
reporting visible+mapped with a non-NULL surface). The process lived on, and
every launcher Activate presented the dead window: the app "wouldn't open"
with zero errors (2026-10-08 incident, diagnosed live on this box).

## What changed

- `linux/gtk-shell/main.c` — `on_activate` verifies the existing window with
  `shell_window_usable()` (an X round-trip: `XGetWindowAttributes` + sync
  under a temporary error handler; libX11 dlopened, X11-gated, conservative
  by design) and destroys + rebuilds when the server reports BadWindow for
  its xid. Banner taps take the same path via `shell_view_usable()`;
  rebuilds reuse the running memory meter instead of stacking a second one;
  `MUSE_DESKTOP_APP_ID` overrides the bus name (default unchanged, invalid
  ids fall back) so an e2e instance runs beside the live app.
- `linux/gtk-shell/muse_desktop_shell.py` — same recovery mirrored
  (`_x11_own_window_alive`, meter guard, app-id override).
- `linux/gtk-shell/build.sh` — `-ldl` for dlopen (the X11 client lib is
  never linked: zero new link deps by design).
- `scripts/e2e-shell-zombie.mjs` + `scripts/fixture-x11-ctl.py` (new) — real
  shell + real host + real X server: map, external kill, launcher-style
  Activate, assert a NEW window maps. RED 2/4 pre-fix, GREEN 4/4 post-fix.
  Registered in `unit-test-all.mjs` + `test:e2e-shell`; skips cleanly
  without X11 / binary / python3 / gdbus.
- `scripts/unit-test-guix-shell.mjs` — 7 new static pins for the recovery
  contract; the tap-rebuild pin follows the widened condition.
- Rail heading: the literal `แผงขวา` title is gone (header keeps the close
  button, right-aligned); toggle/gutter/aside labels reworded to content
  (`Session · ค่าใช้จ่าย`, `ซ่อนแผง`, `ปรับความกว้างแผง`); dead `.rb-title`
  CSS removed. `?v=` + package version → 1.1.34 together (BUG-078).
