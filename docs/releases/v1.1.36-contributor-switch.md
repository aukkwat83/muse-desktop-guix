# v1.1.36 — Contributor on/off switch in the cost rail

Previous: v1.1.35

Follow-up to v1.1.35 (effort default `max`, `ultra` retired, contributor
billing default): the mode had moved into the CLI's settings.json with no
surface in the desktop — the cost rail showed the โหมด badge but the user
had to hand-edit the CLI file to flip it. This release adds the switch.

## What changed

- `src/server/contributor.js` (new in v1.1.35) — `setContributorEnabled()`:
  writes `contributor_mode_enabled` to the CLI settings, preserving every
  other key and keeping a `.bak` of the pre-change file. Enabling also
  records `contributor_mode_disclosure_acknowledged`; disabling leaves it.
  Malformed files are refused, never overwritten.
- `src/server/index.js` — `POST /api/contributor {enabled}`: boolean-only
  (anything else 400s), unwritable file 500s. Pricing already reads the
  file per request, so the rail follows with no restart.
- `src/renderer/rightbar.js` — toggle button under the cost grid
  (`เปิด contributor` / `ปิด contributor`, existing `btn ghost sm` style,
  no new colors): the title carries the data-use notice, so the click is
  the informed consent. Refetches `/api/pricing` and repaints on success,
  re-enables with the error in the title on failure.
- `?v=` + package version → 1.1.36 together (BUG-078).

## Verification

- `unit-test-contributor`: 12/12 (incl. 2 new switch cases: write +

- E2E `POST /api/contributor` step: off→on round-trip against the real

  keys preserved, non-boolean 400s, rejected switches move nothing)
- Full E2E: 92/92. Full gate green except pre-existing environmental
